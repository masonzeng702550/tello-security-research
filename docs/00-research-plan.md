# 研究計畫

## 研究問題

**RQ1（漏洞）** Tello 系統（App + 無人機 + 後端）存在哪些可實際利用的資安弱點？其風險等級為何？

**RQ2（資料主權）** Tello App 在使用過程中蒐集哪些資料、回傳至哪些端點、由誰營運、位於哪個司法管轄區？
實際行為與其隱私權政策的宣稱是否一致？

**RQ3（縱向）** 2019→2024 的六個版本間，第三方 SDK、權限與後端端點如何演變？

> RQ2 是本專案的主軸。RQ1 的控制通道部分已有大量前人成果（見 `01-prior-art.md`），只複現作為基準。

## 判斷紀律（避免最常見的失分點）

- **「DJI 是中國公司 → 有風險」不是證據。** 每一個「回傳境外」的主張都必須有 pcap／端點歸屬佐證。
- **兩條通道分開講**：手機↔無人機（明文 UDP，本地）與 手機↔網際網路（後端）。混談會使結論失焦。
- **否證也是成果**。若查無異常回傳，就據實寫「在 X 版本、Y 情境下未觀測到 Z」，並說明觀測邊界。
- **標明觀測邊界**：沒測到不等於不存在。要寫清楚測了哪些功能路徑、多久、什麼網路環境。
