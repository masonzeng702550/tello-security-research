## P1｜Frida 記憶體 DEX 傾印：解開愛加密的殼

**為何排第一**：F03 記載 89% 的方法主體被抽取，
這是目前**所有**「無法靜態判斷」結論的共同根因。
解開後可一次回答五個以上跨 findings 的未決問題。

### 可解鎖的問題

| 問題 | 出處 |
|---|---|
| `mydjiflight` 請求的 `signature` 欄位如何產生 | F10 |
| pinning 實際載入哪幾張憑證、失敗時是否 fallback | F04 |
| `AreaCodeTello` 的判定來源與寫入點 | F05 |
| 隱私政策的語系選擇邏輯 | F05（核心未決） |
| 完整端點清單（含執行期組出的 URL） | F02 觀測邊界 |
| GameSir 上報的觸發條件與節流邏輯 | F09 |

### 做法

Hook `InMemoryDexClassLoader` 與 `DexFile` 相關 API，
於殼完成還原後自記憶體 dump dex。

**注意 F03／F08 的教訓**：大範圍 Java hook 會與殼衝突導致崩潰。
須沿用 `dynamic/frida/unpin-targeted.js` 的**延遲掛載**策略。
