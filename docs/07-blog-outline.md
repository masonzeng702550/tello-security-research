# 部落格撰寫方向

> 目的：把 18 份 findings 轉成一篇讀得下去、且**經得起查證**的文章。
> 本文件不是大綱模板，而是針對本研究實際素材的編輯建議。

---

## 一、先決定：這篇文章在講什麼

**不要寫成漏洞清單。** 18 項發現攤平列出，讀者記不住任何一項，
而且第一個懂行的人會 Google 三十秒，發現 L1 那幾項早有人發表——文章就毀了。

**要寫成一個研究過程。** 本研究真正稀有的不是漏洞，是**這條軌跡**：

```
找到一個 Critical
   → 自己去查前人研究
   → 發現核心機制早已被發表（CVSS 9.4 都給過了）
   → 公開承認，並精確標註哪些是別人的、哪些是自己的
   → 轉向開案時就標定為缺口的 App 層
   → 在那裡找到七項查無前人研究的發現
```

這條線同時展示三件事：技術執行力、研究判斷力、智識誠實。
**第三項在資安圈特別稀缺**——浮報發現的人太多，主動說「這個別人做過了」的人太少。

## 二、開場：三段之內給出鉤子

不要從「無人機資安近年受到關注……」開始。從**具體的一刻**開始。

### 建議開場素材（擇一）

**A. 從那 7 個位元組切入**

> 我送出了 7 個 ASCII 字元。18 毫秒後，飛機回我 `ok`。
> 4 毫秒後，手機上的畫面全黑了。
> 我試著重新連線——沒有用。47 秒後，畫面依然是黑的。
> 唯一的恢復方式是把飛機關機再開。而飛在天上的無人機，你關不了機。

然後第二段立刻轉折：

> 然後我去查了前人研究，發現這件事早在幾年前就有人發表過了。

這個「高潮→立刻自我打臉」的節奏會讓讀者留下來。

**B. 從隱私政策的矛盾切入**

> App 的繁體中文資源檔有 316 條字串。
> 我數了其中 12 組「中國用語 vs 台灣用語」的對照，
> 結果是 57 : 4——**93.4% 是中國用語**。
> 不是沒做繁中版，是做了，但只做了簡轉繁。

適合把文章定位在資料主權而非漏洞。

**C. 從那張解出來的照片切入**

> 我用一個 `nc` 指令連上自己的無人機，沒有輸入任何密碼，
> 然後從封包裡重組出一張 960×720 的照片——我家客廳。

畫面感最強，但要小心別讓讀者以為這是新發現（它不是）。

## 三、主體結構

### 第一幕：以為找到了大東西

素材（全部有 pcap 與截圖佐證）：

| 事實 | 數字 |
|---|---|
| 攻擊酬載 | `command`，7 個 ASCII 字元 |
| 飛機回應 | `ok`，18 毫秒 |
| 擁有者影像中斷 | 我方封包送出後 4 毫秒 |
| 影像封包數 | 1,766 → 0 |
| 恢復觀測 | 47 秒零恢復；App 內重連無效 |
| 唯一恢復方式 | 關閉飛機電源 |

**關鍵細節**：App 的控制流在整段期間維持 **49–51 Hz 正常運作**。
使用者以為連線正常，實際上已看不到任何畫面。這個細節比「影像斷了」更有畫面感。

**可用圖**：`FIG-02-statusbar-only-safe-to-publish.png`（狀態列前後對照，不含住家畫面）

### 第二幕：查證，然後打臉自己

這一幕是文章的核心，不要簡略帶過。

寫清楚查到了什麼：

- Alias Robotics 的案例研究：**RVDP#1208**，Tello Wi-Fi 預設無密碼，**CVSS 9.4**
- 同儕審查論文：《Analysis of Control Channel Cybersecurity of the Consumer-Grade
  UAV by the Example of DJI Tello》
- 公開技術文章：明載可「disconnect connected phones and mark themselves as the controller」

然後誠實地說：**「我找到的東西，核心機制別人已經發表過了。」**

接著才講增量——而且要講得精確：

> 但前人多以「Tello 沒有認證」一語帶過。我實測後發現這句話不完整：

| 增量 | 內容 |
|---|---|
| 兩條路徑的安全模型**相反** | App 的二進位協定**具**工作階段綁定；SDK 純文字協定**完全沒有** |
| WPA2 密碼**無法緩解** | 實測設定密碼後攻擊照舊成立 |
| **不可恢復** | 47 秒零恢復，僅能關閉電源 |

第一項最有價值——它**修正了一個流傳的簡化說法**。

### 第三幕：轉向 App 層，找到真正沒人做過的

這裡放七項查無前人研究的發現。**不要平鋪直敘，挑一項當主角。**

**建議主角：F09**

> 一個第三方手把 SDK 在 App 啟動時，把裝置廠牌、機型、套件名
> 送到 `client.vgabc.com`——解析至中國境內的阿里雲。
>
> 我檢索了四個版本、中英文兩種隱私政策，`gamesir`、`vgabc`、`小鸡`
> 的命中數**全部是零**。
>
> 然後我做了個對照實驗：把位置、相片、影片、儲存空間六項權限**全部拒絕**，
> 重跑一次。
>
> **請求照樣送出，payload 與六項全部授予時逐位元組相同。**

為什麼？因為送的欄位全都可以從 `android.os.Build` 拿到，不需要任何危險權限。

**這句話值得單獨成段**：

> 使用者既不知道它存在，也無法用任何設定阻止它。

**方法論細節值得寫**（讀者會學到東西）：這個 A/B 測試差點做錯——
GameSir SDK 有節流機制，如果不先把 `gamesir_lastTime` 歸零，
**兩組都會因節流而無流量**，那個「零差異」會被誤讀成「權限無影響」。
結論碰巧正確，但論證是無效的。

配角（各給一到兩段）：

- **F14** — 客服頁面載入阿里雲 ARMS 與 Google Analytics，含**持久性使用者識別碼**
- **F05** — 揭露落差是**對稱的**：中文版揭露百度／騰訊、英文版揭露 Google，兩份都不完整
- **F13** — 飛行日誌的混淆：`plain[i] = cipher[i] ^ cipher[2]`，**金鑰跟密文放在一起送**
- **F17** — 百度的 `.so` 還在包裡，但 JNI 進入點指向的類別已全部消失

### 第四幕：我搞錯的四件事

**這一幕是本文章最可能被轉發的部分。** 大多數技術文章不寫這個。

| 我當時的推論 | 實驗結果 |
|---|---|
| 「序號恆為 0，所以可注入飛行指令」 | 滿舵、21.5 秒、飛手手離開搖桿——**飛機零反應**。嚴重度從 High 下修到 Low |
| 「設 Wi-Fi 密碼可以擋住攻擊」 | 首次測試顯示有效，但那是 n=1 且與機制認知衝突。重測後攻擊完整重現 |
| 「隱私政策從沒提過 Google Analytics」 | 查證後為誤，英文版三個版本都有。修正後反而發現「落差是對稱的」這個更好的框架 |
| 「日誌熵值 7.97，接近隨機、解不開」 | 只是還沒找到金鑰。找到後熵降到 6.36 |

第二項特別值得展開——**如果我止於單次測試，會寫出一篇建議讀者「設個密碼就安全了」的文章。**
那個建議方向完全相反，而且會誤導人。

第四項可以帶出一句有記憶點的話：

> 高熵只代表「以目前的假設看起來像隨機」，不代表強加密。

讀者不會因為你誠實而覺得研究弱，但會因為你被抓到浮報而不再信任整篇。

## 五、可以獨立成篇的支線

若一篇塞不下，這四條都夠獨立寫一篇：

1. **「我差點寫出方向完全相反的資安建議」** — WPA2 偽陰性的完整過程。
   談 n=1、談與機制認知衝突時該做什麼、談重測的價值。

2. **「89% 還是 39%？一個母體定義的錯誤」** — 我用全 dex 當母體量出 39% 樁比例，
   一度判定自己先前的 89% 是錯的。按套件拆開才發現殼放過了 `android/support/*`，
   而那佔近三成方法，把 96.7% 稀釋掉了。**質疑一個比例前，先確認雙方母體一致。**

3. **「金鑰就放在密文旁邊」** — 飛行日誌解碼的完整推理過程，
   包含兩個被否證的假設，以及「記錄內有長串重複」＋「跨記錄同位置熵為 8.0」
   這兩個觀察的交集如何指向正解。

4. **「教學用的 API 就是攻擊用的 API」** — Tello EDU、Scratch、`djitellopy` 與
   官方 SDK 文件（`auth` 出現 0 次）。適合寫給教育工作者看。
