# 威脅模型

系統由三個元件組成，兩條完全不同性質的通道。**分析與結論必須分開陳述。**

```
   ┌──────────────┐   通道 1：Wi-Fi (Tello 自建 AP，開放無密碼)     ┌──────────┐
   │  Tello 無人機 │ ←──────────────────────────────────────────→ │  手機 App │
   │  (韌體)      │   UDP 8889 命令 / 8890 狀態 / 11111 視訊       │          │
   └──────────────┘   明文、無認證、無綁定                          └────┬─────┘
                                                                        │
                                            通道 2：行動網路 / 家用 Wi-Fi │ HTTPS
                                                                        ↓
                                                          ┌──────────────────────┐
                                                          │ Ryze / DJI 後端       │
                                                          │ + 第三方分析 SDK 端點 │
                                                          └──────────────────────┘
```

> **關鍵限制**：手機連上無人機 AP 時，通常沒有外部網路。
> 兩條通道**在時間上是互斥的**。這造成一個必然的設計：飛行資料若要回傳，
> 必須先落地本地、待恢復網路後補傳。**這條時間差路徑是本專案的重點觀測對象。**

---

## L1 — 近場攻擊者（Wi-Fi 涵蓋範圍內）

**攻擊者能力**：物理上位於無人機 Wi-Fi 訊號範圍內，持有一般筆電與無線網卡。無需帳號、無需事前接觸。

| 威脅 | 前提 | 影響 | 前人已證實 |
|---|---|---|---|
| 未授權連線 | AP 開放無密碼 | 完全控制 | ✅ |
| 控制權接管 | 送出 `command` 宣告為控制端 | 原操作者失去控制、可能墜機 | ✅ |
| de-auth 後劫持 | 有設密碼時，先踢掉原操作者 | 同上 | ✅ |
| 視訊竊聽 | 11111 明文 H.264 | 即時影像外洩 | ✅ |
| 指令注入 / 重放 | 無序號、無時戳、無 MAC | 任意飛行指令 | ✅ |
| **韌體升級路徑濫用** | App 可對無人機推韌體 | **持久化控制** | ❓ **待研究** |

> L1 前五項已被充分研究，本專案僅**複現以建立基準**。
> **第六項（韌體升級通道）是缺口** — 升級封包是否簽章驗證？能否推入未簽章韌體？值得投入。

**風險評估的誠實面**：需要物理接近（Wi-Fi 範圍約數十公尺），且無人機需開機。
實務衝擊有限，但對「教學現場多台同時飛行」的場景是真實問題（誤連／互相干擾／惡作劇接管）。

## L2 — 同裝置的惡意 App

**攻擊者能力**：使用者手機上安裝了另一支無特權（或低權限）的第三方 App。

| 威脅 | 檢查點 |
|---|---|
| exported component 被外部喚起 | `AndroidManifest.xml` 的 `android:exported="true"`、無 permission 保護的 Activity/Service/Receiver/Provider |
| 本地資料可讀 | `/data/data/com.ryzerobotics.tello/` 檔案權限；飛行紀錄／影像是否明文落地 |
| 外部儲存外洩 | `targetSdk 30` 是否豁免分區儲存；影像存到 `/sdcard/` 是否任何 App 可讀 |
| WebView 弱設定 | `setJavaScriptEnabled` + `addJavascriptInterface` + 載入遠端內容 |
| 自訂 URL scheme 劫持 | deep link 是否可被其他 App 攔截 |
| 明文流量 | `network_security_config.xml` 的 `cleartextTrafficPermitted` |

> `targetSdk 30`（2024 年釋出的 App）在此層特別值得追：舊 targetSdk 會豁免掉多項 Android 隱私強化。

## L3 — 供應鏈與資料主權

**攻擊者/風險來源**：App 發行者、其第三方 SDK 提供者、以及可依當地法律取得資料的政府。

| 威脅 | 檢查點 | 必要證據 |
|---|---|---|
| 個資回傳境外 | 端點 IP / ASN / WHOIS / TLS SNI | pcap + 歸屬查詢輸出 |
| 第三方分析 SDK 蒐集 | jadx 找 SDK 套件名；hook 其上報函式 | 反編譯路徑 + 攔截到的 payload |
| **繞過商店的自我更新** | 是否存在下載 APK 並觸發安裝的程式路徑 | 反編譯路徑 + 實際觀測到的下載請求 |
| 政策宣稱與實作落差 | 政策原文逐條 vs 實際 payload 欄位 | 落差對照表 |
| 停售後的遺留風險 | 後端關站後 App 行為；權限仍在 | 動態觀測 |

### 這一層的舉證標準（最重要）

| ❌ 不可接受 | ✅ 可接受 |
|---|---|
| 「DJI 是中國公司，所以資料會被拿走」 | 「v1.6.8.0 在 X 操作下向 `<host>` 送出 POST，body 含 `<欄位>`，該 host 解析至 `<IP>`，屬 ASN `<n>`（`<營運商>`，註冊地 `<國>`」 |
| 「反編譯看到有這個 URL，所以有回傳」 | 「反編譯見於 `<檔案:行>`，且動態觀測到實際請求（pcap `#n`）」 |
| 「這個 SDK 很可怕」 | 「該 SDK 的 `<函式>` 在 `<情境>` 被呼叫，上報欄位為 `<清單>`」 |

**沒有動態證據的靜態發現，只能寫成「存在此程式路徑，本研究未觀測到其被觸發」。**

## 不在範圍內

- 對他人持有的無人機進行任何測試
- 對 Ryze/DJI 生產環境後端進行任何主動測試（掃描、fuzzing、帳號攻擊）——只做被動流量觀察
- GPS 欺騙 / RF 干擾（涉及頻譜法規，且 Tello 無 GNSS）
- 破解／散布韌體或 App 二進位檔
