# F16 — 7 個明文位元組即可切斷擁有者的影像連線並取得完整飛行遙測

| 欄位 | 內容 |
|---|---|
| 編號 | F16 |
| 層級 | L1 近場 Wi-Fi |
| 分類 | 認證缺失 / 阻斷服務 / 機密性 |
| 嚴重度 | **Critical** |
| 受影響版本 | 韌體 `01.01.0083`（與 App 版本無關） |
| 狀態 | **T2 — 直接實測** |
| 對應測試 | TC-L1-09（新增），承接 F12 的「雙通道競態」待辦 |
| 證據 | `pcap:TC-L1-09-sdk-concurrent.pcap`、`screenshot:20260825-03` |

## 摘要

Tello 除了官方 App 使用的私有二進位協定外，另支援**純文字的 SDK 協定**。

實測顯示：**在擁有者的 App 完全正常連線的狀態下**，
自未經認證的來源送出 **7 個 ASCII 字元 `command`**，即造成

1. 飛機於 **18 毫秒**內回覆 `ok`，進入 SDK 模式
2. **擁有者的影像串流立即中斷**（App 畫面全黑、顯示斷線圖示）
3. 飛機開始向攻擊者廣播**明文的完整飛行遙測**

且該影像中斷**只能靠關閉飛機電源恢復**——而飛行中的無人機無法關機。

F15 的 `conn_req` 路徑在已有客戶端連線時會被拒絕。
**SDK 路徑沒有這個限制。**

## 與 F15 的關鍵差異

| | F15 的 `conn_req` 路徑 | **本findings的 SDK 路徑** |
|---|---|---|
| 擁有者未連線時 | ✅ 成功 | （未單獨測試） |
| **擁有者連線中時** | ❌ **被拒** | ✅ **成功** |
| 對擁有者的影響 | 無 | **影像連線中斷** |
| 攻擊酬載 | 11 bytes 二進位 | **7 bytes 純 ASCII** |
| 需要協定知識 | 需理解二進位框架與 CRC | **無**——公開文件的 SDK 指令 |

→ **本findings的攻擊門檻遠低於 F15，且效果更嚴重。**

## 實測

### 條件

| 項目 | 設定 |
|---|---|
| 官方 App | **正常連線中**，影像串流運作，IMU 已校準無告警 |
| 攻擊酬載 | ASCII 字串 `command`（7 bytes），無標頭、無 CRC |
| 來源 | 埠 `45998`，Android 內建 `nc`，未提供任何憑證 |
| 安全限制 | **僅送出查詢類指令**，未送出任何會產生動作的指令 |

### 時間軸

```
t= 10.106 s   我方 45998 → 8889    "command"
t= 10.124 s   飛機 8889  → 45998   "ok"                    ← 18 ms
t= 10.11  s   App 影像串流停止
t= 10.228 s   飛機 8889  → 8890    "pitch:0;roll:1;yaw:8;…"
```

### 對擁有者影像的影響

| 區間 | App 影像封包數 |
|---|---|
| 我方封包前（0–10.1 s） | **1,583** |
| 我方封包後（10.1–20 s） | **3** |

影像串流於 `t=10.11s` 終止——**與我方封包相隔 4 毫秒**。

截圖佐證（`20260825-03-after-sdk-command.png`）：
App 畫面全黑、Wi-Fi 圖示帶斷線斜線、操控元件變暗。
對照測試前的截圖，該畫面原本有即時影像。

> App 的**控制流並未停止**（1,736 個封包，我方封包後仍有 482 個）。
> 亦即 App 仍在送指令，但**收不到影像**——
> 使用者在飛行中會是「操控還在、畫面全黑」的狀態。

### 攻擊者取得的遙測

飛機自 `t=10.23s` 起持續廣播（281 個封包，至 35.4 s）：

```
pitch:0;roll:1;yaw:8;vgx:0;vgy:0;vgz:0;templ:70;temph:73;
tof:10;h:0;bat:85;baro:49.44;time:0;agx:1.00;agy:-27.00;agz:-999.00;
```

| 欄位 | 內容 |
|---|---|
| `pitch` / `roll` / `yaw` | 三軸姿態 |
| `vgx` / `vgy` / `vgz` | 三軸速度 |
| `agx` / `agy` / `agz` | 三軸加速度 |
| `templ` / `temph` | 機體溫度範圍 |
| `tof` / `h` | 測距感測器高度 / 氣壓高度 |
| `bat` | **電量百分比** |
| `baro` | 氣壓計 |

**純文字、無加密、無認證。**

## 恢復性：唯一的恢復方式是關閉飛機電源

攻擊造成的影像中斷**不會自行恢復，也無法由 App 內操作恢復**。

### 實測一：是否自行恢復

```
我方送出 command        t = 12.096 s
最後一個影像封包        t = 12.080 s      ← 相隔 16 毫秒
```

| 區間 | App 影像封包數 |
|---|---|
| 攻擊前（0–12.1 s） | **1,766** |
| 攻擊後 +0 ~ +10 s | **0** |
| 攻擊後 +10 ~ +25 s | **0** |
| 攻擊後 +25 ~ +47 s | **0** |

**47 秒內沒有任何一個影像封包。** 截圖佐證（`20260825-05`）：
畫面全黑、Wi-Fi 圖示維持斷線狀態。

同一期間：

- **App 的控制流持續運作**（2,893 個封包，至 59 s 仍在送）
  → App 不知道自己被切斷，使用者仍以為連線正常
- **飛機持續向攻擊者廣播遙測**（507 個封包）

### 實測二：能否由 App 內恢復

使用者實際嘗試在 App 內重新連線（點選連線狀態、退回連線畫面重按「連接」）：

> **完全無法恢復。**
> 必須**關閉飛機電源再開機**，之後於連線畫面重新連線，影像才會回來。

### 這決定了本findings的實務嚴重度

**飛行中的無人機無法關閉電源。**

若同一機制於飛行途中發生，使用者將面臨：

| 狀態 | 情形 |
|---|---|
| 影像 | **永久中斷**，該次飛行內無法恢復 |
| 控制 | App 仍在送指令（是否仍有效見下方觀測邊界） |
| 可用的恢復手段 | **無**——關機需要接觸機體 |

→ 實際效果為**被迫盲降**：使用者只能憑肉眼目視距離操控降落，
   若無人機已飛出視線範圍，等同失去該機體。

> ⚠️ **本節的飛行中情境為推論。** 上述實測皆在**地面**進行。
> 「飛行中影像同樣不可恢復」是基於相同機制的合理推斷，
> **但本研究未於實際飛行中測試**。

## 影響評估

### 已實測

- 未經認證即可**切斷擁有者的影像連線**
- 未經認證即可**取得完整即時飛行遙測**
- 攻擊酬載為 7 個 ASCII 字元，**不需要任何協定逆向知識**
- 在**擁有者正在使用**的狀態下成立

### 推論（**未實測**，見觀測邊界）

進入 SDK 模式後，Tello 的公開 SDK 指令集包含：

| 指令 | 效果 |
|---|---|
| `takeoff` / `land` | 起飛 / 降落 |
| `rc a b c d` | **直接搖桿控制**，四軸值以純文字表示 |
| `emergency` | **立即停止所有馬達** |

若這些指令在同樣條件下可執行，則**飛行中劫持與強制墜落成立**。

> ⚠️ **本研究未測試上述任何指令。**
> 它們會使飛機產生實際動作或墜落，
> 依 `docs/03-ethics-legal.md` 須在空曠場地、備妥防護、
> 並依 `docs/procedures/TC-L1-03-injection-field-test.md` 的程序執行。
> **在測試完成前，不得宣稱「攻擊者可使飛機墜落」。**

## 攻擊前提

與 F12／F15 相同——攻擊者需位於 Tello 的 Wi-Fi 網段內。
而該網路實測為 **`open`（無密碼）**，門檻為零。

## ⚠️ 觀測邊界

- **未測試 `rc`、`takeoff`、`land`、`emergency`。** 上節的「推論」僅為攻擊面分析。
- **未確認影像中斷的機制**。可能是飛機切換至 SDK 模式時停止原有影像串流，
  也可能是連線狀態被覆寫。本findings只記錄**觀測到的因果時序**（相隔 4 ms），
  未解析飛機內部的狀態機。
- ~~未測試擁有者能否自行恢復~~ → **已實測：無法。** 僅能關機重開（見上）。
  惟該測試在地面進行，**飛行中的行為未實測**。
- 後續的 `battery?`、`sdk?` 兩個查詢**實際上未送出**
  （擷取中僅見一個我方封包），故未驗證 SDK 模式下的其他查詢指令。
- 僅一台機器、一個韌體版本。
- 未測試設定 Wi-Fi 密碼後本攻擊是否失效。
