# F05 — 中英文隱私政策的揭露落差：英文版六年未改且從未揭露任何第三方 SDK

| 欄位 | 內容 |

| 層級 | L3 供應鏈與資料主權 |
| 分類 | 隱私 / 揭露 |
| 嚴重度 | **High**（揭露落差，非技術漏洞） |

## 摘要

每個版本的 APK 都內建中英文兩份隱私政策。比對六個版本後發現：

- **英文版自 2019 至 2024 位元組完全相同**（SHA-256 一致），六年零修改
- **中文版改了三次**
- **英文版從頭到尾未提及任何第三方 SDK**（Bugly、Baidu 皆 0 處）
- **中文版曾明確列出 BaiduLBS 蒐集 Android ID 與 MAC 位址**，但該揭露在 1.6.8.0 被整段刪除
- **中文版明示資料儲存於中華人民共和國境內**，英文版無對應聲明

## 證據：附件一「第三方 SDK 說明」的演變

### 1.6.0.1（2022-03）— 附件一首次出現，只列 Bugly

> 以下列举了我们目前采用的第三方 SDK 名称和收集使用目的…
> **第三方SDK名称｜收集使用目的｜第三方隐私政策链接**
> **Bugly｜崩溃信息收集｜https://bugly.qq.com/v2/contract**

### 1.6.4.0（2022-09）— 附件一擴充，新增 BaiduLBS 與資料類型欄位

> **第三方SDK名称｜使用目的｜信息类型｜第三方隐私政策链接**
> **Bugly｜崩溃信息收集｜设备信息：Android id信息｜https://bugly.qq.com/v2/contract**
> **BaiduLBS｜定位服务｜设备信息：Android id信息、设备MAC 地址｜https://lbsyun.baidu.com/…**

→ 廠商自行揭露：百度定位 SDK 蒐集 **Android ID 與裝置 MAC 位址**。

### 1.6.8.0（2024-09）— 附件一整段刪除

- 全文中**無「附件一」**、無「第三方SDK名称」、無 Bugly、無 Baidu
- 正文第三節指向附件的那句話也一併刪除：

  1.6.4.0：「…请详见**本政策附件一第三方SDK说明**。」
  1.6.8.0：該句**不存在**

**重現方式**：`static/privacy-policy/` 下的抽取文字，
原始 HTML 位於各版 `assets/`。

## 證據：儲存地點與跨境傳輸

### 中文版（1.6.4.0 與 1.6.8.0 文字相同）

> **上述信息将存储于中华人民共和国境内。如需跨境传输，我们将会按照法律法规的要求开展安全评估。**

### 英文版（六版皆同）

全文 28,679 字元中：
- `Bugly` — **0 處**
- `Baidu` — **0 處**
- `third-party SDK` — **0 處**
- 關於資料所在地：**僅有一段 EEA（歐洲經濟區）移轉條款**，
  說明資料可能移轉至 EEA 以外並會採取保護措施。
  **沒有任何關於一般性儲存地點的聲明，未提及中華人民共和國。**

## 判讀

### 揭露落差的具體樣貌

| | 中文版 | 英文版 |
|---|---|---|
| 2019–2024 改版次數 | 3 次 | **0 次** |
| 第三方 SDK 揭露 | 有（1.6.0.1–1.6.4.0） | **從未有過** |
| 具名 Baidu 定位 SDK | ✅ 1.6.4.0 | ❌ |
| 揭露蒐集 Android ID / MAC | ✅ 1.6.4.0 | ❌ |
| 儲存地點聲明 | 明示中國境內 | 無 |

在 1.6.4.0 這個版本，**同一支 App 內建的兩份政策，
對「有沒有百度定位 SDK 在蒐集你的 Android ID 和 MAC 位址」給出了不同答案。**

### 1.6.8.0 刪除附件的兩種解讀

- **(a) 一致性修正** — SDK 真的移除了，所以揭露也移除。合理。
- **(b) 揭露減少但蒐集持續** — 若百度 SDK 仍在（見 F01／F03 的未決疑點），
  則刪除揭露的同時保留了蒐集。

**這正是 F01 未決疑點的重要性所在。** 若 (b) 成立，
本發現的嚴重度會從「揭露不對等」升級為「揭露與實際不符」。

### 為什麼 1.6.4.0 的揭露對後續測試特別有用

廠商自己講明了 BaiduLBS 蒐集 **Android ID 與 MAC 位址**。
這給了動態測試（TC-L3-04）明確的觀測標的——
不必猜要找什麼欄位，直接驗證這兩項是否出現在上行流量中。

## 追加：線上版是第三份不同的文件（2026-08-17）

先前僅比對 APK **內建**的兩份政策。取得線上版後，發現共有**三份內容不同的文件**。

### 取得方式與觀測位置

```
來源   https://www.ryzerobotics.com/zh-tw/policy
時間   2026-08-17
位置   自台灣連線
```

**站台強制依地區路由**：`/en/policy`、`/cn/policy`、`/jp/policy`、`/kr/policy`
**皆被導回 `/zh-tw/policy`**，URL 路徑無效。`/zh-cn/` 回 404。
站台為 SPA，內容由 JS 渲染，`curl` 對所有語系只能取得同一份 60,564 bytes 的殼。

→ **自台灣連線時，無法透過 URL 取得英文版線上政策。**

### 三份文件比較

| | 內建 EN | 內建 ZH (1.6.8.0) | **線上（台灣區）** |
|---|---|---|---|
| 語言 | 英文 | 簡體中文 | **簡體中文** |
| 純文字長度 | 28,679 | 6,826 | **2,650** |
| 第三方 SDK 揭露 | ❌ 從未有 | 曾有，1.6.8.0 已刪 | ❌ 無 |
| 資料儲存地 | 僅 EEA 移轉條款 | 明示「存储于中华人民共和国境内」 | 未提儲存地 |
| 境外第三方 | — | — | ✅ 明示（見下） |

**三份文件對「你的資料在哪、誰能拿到」給出三種不同的說法。**

### 線上版獨有的揭露項目

以下項目**兩份內建政策皆未出現**：

**蒐集範圍**
> 姓名、电话号码、电子邮箱地址、通讯地址、**身份证号码**、
> **银行卡卡号**、**飞行数据（包括传感器数据、导航系统数据、设备数据、
> 控制类数据、限飞数据和环境感知视觉数据）**

「**环境感知视觉数据**」即視覺／攝影機資料。
對照 F06 已實測確認的 11111 明文視訊串流，這一項值得追。

**敏感資訊**
> 您的个人信息中可能含有敏感信息，例如您的**种族、宗教信仰、
> 个人健康状况、性别取向**等

**境外第三方的揭露義務**
> 我们可能委托其他第三方代表睿炽科技提供服务…
> 这些第三方**可能来自境外**，根据其所在地的法律，
> 这些**境外第三方可能负有一定的信息披露义务**。

**強制揭露情形**
> 1）在涉嫌犯罪活动时，向司法或执法机构披露…
> 2）根据法律（或法院）的强制要求披露；
> **3）根据政府的强制要求披露**；
> 4）为保护睿炽科技的资产…

**適用法律與年齡門檻**
> 深圳市睿炽科技有限公司是**依据中华人民共和国法律成立**的有限责任公司
>
> 如果您**未满十五岁**，您应该获得父母或监护人的同意和指导

年齡門檻 15 歲對應中國個資保護法的規定，
與 COPPA（13 歲）或 GDPR（16 歲）皆不同。

### 一項頁面呈現的觀察

該頁頁尾顯示地區標示為「**中國台灣**」、語言標示為「**繁體中文**」，
但**實際供應的內文為簡體中文**。語言標示與內容不符。

此為對廠商網站呈現方式的事實記錄，不引申其他推論。

### 對本findings的意義

原本的立論是「同一支 APK 內建的中英文政策揭露不對等」。
加入線上版後，範圍擴大為：

**廠商在三個管道（英文內建、中文內建、線上）提供三份內容不同的政策，
且從台灣連線時無法取得英文線上版。**

一般使用者若依 App 內連結查看政策，看到的是內建版；
若依政策末段的指示「登录睿炽科技主页…并点击其下方隐私政策链接」
查看最新版，從台灣得到的是簡體中文的線上版。
**兩者內容不同。**

## ⚠️ 觀測邊界

1. **未確認台灣使用者實際會看到哪一份政策。**
   語系選擇邏輯**不在可見的 smali 中**（已檢索 `Privacy_Policy`、`ZH_`、
   `Locale`、`"zh"` 等關鍵字，皆無命中），
   研判位於加殼的加密 payload（見 F03）。**待動態驗證。**

2. 中文政策的「儲存於中國境內」聲明，可能是針對中國使用者的
   個資保護法（PIPL）合規陳述，未必適用於境外使用者。
   **但英文版對境外使用者的資料落地位置完全沉默**，這件事本身成立。

3. ~~這些是 APK 內建副本，與線上版本可能不同~~ → **已於 2026-08-17 取得線上版比對**（見上）。
   但線上版僅取得自台灣連線的結果，其他地區可能不同。

4. 本findings為**揭露落差**，不等同於違反特定法規。
   是否構成法遵問題需法律意見，本研究不作此主張。

## 附帶更正

先前以關鍵字「百度」掃描各版政策，六版皆 0 命中，一度誤判為「從未揭露百度」。
**實際上附件一寫的是拉丁字「BaiduLBS」**，中文字串搜尋為假陰性。
已改以 `(?i)baidu` 與 `lbsyun` 複核。

> 教訓：跨語言文件的關鍵字檢索，必須同時涵蓋中英文與品牌拉丁拼寫。
