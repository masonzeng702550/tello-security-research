# F05 — 隱私政策的揭露落差：英文版從未揭露具名第三方 SDK，且內建副本停留在舊版

## 摘要

每個版本的 APK 都內建中英文兩份隱私政策。比對六個版本後發現：

- **英文版自 2019 至 2024 位元組完全相同**（SHA-256 一致），六年零修改
- **中文版改了三次**
- **中文版曾具名列出 `BaiduLBS` 蒐集 Android ID 與 MAC 位址**，
  該揭露在 1.6.8.0 被整段刪除
- **英文版從頭到尾沒有任何具名第三方 SDK 揭露**（Bugly、Baidu 皆 0 處）
- **線上英文版已更新（兒童年齡門檻 15→16），但 APK 內建副本仍是舊版**

> ⚠️ 初稿曾主張「英文版未提及資料儲存於中國」，**該主張為誤**，已於文中更正。
> 英文版實際上明示伺服器位於美國、中國、香港。

## 判讀

### 揭露落差的具體樣貌（已依上述更正修訂）

| | 中文版 | 英文版 |
|---|---|---|
| 2019–2024 改版次數 | 3 次 | **0 次** |
| **具名第三方 SDK 揭露** | ✅ 有（1.6.0.1–1.6.4.0） | ❌ **從未有過** |
| 具名 BaiduLBS | ✅ 1.6.4.0 | ❌ |
| 揭露蒐集 Android ID / MAC | ✅ 1.6.4.0 | ❌ |
| 資料所在地 | 明示「中華人民共和國境內」 | ✅ **明示美國、中國、香港** |
| EEA 資料控管者 | 未提 | ✅ 明示 DJI GmbH |

**修訂後的核心落差不在「資料落地位置」——英文版揭露得相當清楚，
甚至比中文版更完整（明列美中港三地，並指名 DJI GmbH）。**

**真正且唯一存續的落差是「具名的第三方 SDK 揭露」**：

在 1.6.4.0 這個版本，中文政策的附件一逐項列出
`BaiduLBS｜定位服务｜设备信息：Android id信息、设备MAC 地址`，
**英文政策從頭到尾沒有任何等同的揭露**——
不只沒有 BaiduLBS，連「本 App 內嵌第三方 SDK」這件事本身都沒說。

→ 只讀英文政策的使用者，**無從得知有一個中國定位 SDK 正在蒐集
其 Android ID 與裝置 MAC 位址**。這一點成立，且是本findings的核心。

### 1.6.8.0 刪除附件的兩種解讀

- **(a) 一致性修正** — SDK 真的移除了，所以揭露也移除。合理。
- **(b) 揭露減少但蒐集持續** — 若百度 SDK 仍在（見 F01／F03 的未決疑點），
  則刪除揭露的同時保留了蒐集。

**這正是 F01 未決疑點的重要性所在。** 若 (b) 成立，
本發現的嚴重度會從「揭露不對等」升級為「揭露與實際不符」。

### 為什麼 1.6.4.0 的揭露對後續測試特別有用

廠商自己講明了 BaiduLBS 蒐集 **Android ID 與 MAC 位址**。
這給了動態測試（TC-L3-04）明確的觀測標的——
不必猜要找什麼欄位，直接驗證這兩項是否出現在上行流量中。

### 判讀

**1. 年齡門檻 16 不是 EEA 專屬變體。** 美國與義大利判定下皆為 16，
   確認為全球通用的英文線上版。初稿的 EEA 變體推測已排除。

**2. 廠商確實實作了地區性法遵功能，但台灣區兩者皆無：**
   - 美國區有 **CCPA/CPRA 的「Do Not Sell Or Share My Personal Information」**法定連結
   - 美國／EEA 區有 **Cookie 同意橫幅**（Cookie Preferences／Reject All／Accept All）
   - **台灣區兩者都沒有**，且只供應一份 2,650 字元的簡體中文政策

**3. 台灣區的頁面標示與內容不符**：
   頁尾標示語言為「**繁體中文**」，實際供應的內文為**簡體中文**；
   地區標示為「**中國台灣**」。

> 上述為對廠商網站呈現方式的事實記錄。
> 各地區的法遵要求本就不同（CCPA 適用加州、GDPR 適用 EEA），
> 台灣無等同的強制連結要求，故「台灣區未提供該連結」本身不構成違規。
> 本研究僅記錄差異，不主張其法律效果。

**但可據以陳述的是**：同一廠商對不同地區使用者，
在**政策語言、篇幅、內容與可用的隱私控制項**上存在系統性差異，
而台灣區取得的是其中最精簡的一份。

### 對本findings的意義

原本的立論是「同一支 APK 內建的中英文政策揭露不對等」。
加入線上版後，範圍擴大為：

**廠商在三個管道（英文內建、中文內建、線上）提供三份內容不同的政策，
且從台灣連線時無法取得英文線上版。**

一般使用者若依 App 內連結查看政策，看到的是內建版；
若依政策末段的指示「登录睿炽科技主页…并点击其下方隐私政策链接」
查看最新版，從台灣得到的是簡體中文的線上版。
**兩者內容不同。**

## 追加：一個從未被揭露的第三方（2026-08-17 實測）

本findings原本聚焦於「中文版曾揭露 BaiduLBS、英文版從未揭露」。
動態測試後發現一個**兩種語言、所有版本皆未揭露**的第三方：

**GameSir／小雞科技 SDK（`com.xj.gamesir`）**
於 App 啟動時將裝置品牌、型號、套件名送往
`https://client.vgabc.com/clientapi/`（中國境內阿里雲）。

檢索結果：`gamesir`／`小鸡`／`小雞`／`vgabc`／`xj`
在 1.3.0.0、1.6.0.1、1.6.4.0、1.6.8.0 的中文政策與英文政策中
**命中數皆為 0**。

而 1.6.4.0 的附件一——廠商最詳盡的一次揭露——僅列 `Bugly` 與 `BaiduLBS`。

→ 本findings的落差因此不只是「中英文之間」，
   而是**存在一個對所有使用者、所有語言都未揭露的第三方傳輸**。

完整證據與 payload 見 **F09**。

## 追加：App 已正確判定地區為 TW，仍套用簡體中文（2026-08-17）

這是本findings目前**最強的一項證據**，它排除了最有利於廠商的那個解釋。

### 觀測

App 的 `shared_prefs` 中存有：

`file:/data/data/com.ryzerobotics.tello/shared_prefs/share_date.xml`

```xml
<map>
    <int name="spRockerMode" value="1" />
    <string name="AreaCodeTello">TW</string>     ← App 自行判定並儲存
    <int name="DisclaimerShowState" value="1" />
</map>
```

> 附帶觀察：App 同時存在 `share_data.xml` 與 `share_date.xml` 兩個檔案
> （`data` / `date`，疑為 typo），各存不同資料，兩者都在使用中。

### 為什麼這一項是決定性的

在此之前，「台灣使用者看到簡體內容」有兩種可能的解釋：

| 解釋 | 意涵 |
|---|---|
| (a) App 未能判別地區，一律 fallback 到簡中 | 技術疏漏 |
| **(b) App 已判定為台灣，仍套用簡中** | **設計選擇** |

`AreaCodeTello = TW` **排除了 (a)**。
App 明確知道裝置位於台灣，並將該判定持久化儲存，
卻仍在網路請求中送出 `language: zh_cn`（見 F10），
且介面與政策內文均為簡體。

→ 這**不是偵測失敗，是分類決定**：
   在此系統中，台灣被歸入簡體中文的語言區。

| App 介面 | 協議標題繁體，條款內文簡體 | F08 |
| 網路協定 | 送出 `language: zh_cn` | F10 |
| **App 內部狀態** | **`AreaCodeTello = TW`** | **本節** |

前三項顯示結果，第四項顯示**App 內部確實握有正確的地區資訊**。

### 尚未確認的部分

- **`AreaCodeTello` 的判定來源未確認**。可能為 SIM 國碼（MCC）、
  網路註冊國、或系統 locale。**未以 Frida 追出寫入點**，故不宜斷言。
- **未確認 `AreaCodeTello` 是否參與政策語系的選擇**。
  已證明的是「App 握有 TW 這個值」與「App 呈現簡體」同時成立，
  **尚未證明兩者之間的因果連結**。
- 值得注意的是：此判定在**位置權限全部拒絕**的情況下仍然成立（見 F11），
  即地區判定不依賴位置權限。

## 追加：落差是**對稱的**，不是單向的（2026-08-18）

本findings原本記錄的是單一方向的落差：
**中文版揭露 `BaiduLBS`，英文版沒有。**

F14 的檢索發現**反方向同樣成立**：

| 第三方 | 中文政策 | 英文政策 |
|---|---|---|
| `Bugly` | ✅ 4 次 | ❌ 0 次 |
| `BaiduLBS` | ✅ 1 次 | ❌ 0 次 |
| **`Google Analytics`** | ❌ **0 次** | ✅ **三版皆有揭露** |

英文政策 Cookie Policy 章節的原文：

> we use Google Analytics to collect and process certain analytics data

中文政策有 62 處 `Cookie`、92 處「第三方」、12 處「统计」，
但**從未點名任何分析類第三方**；「统计、分析」皆指睿炽自身對資料的處理。

### 這改變了本findings的性質

原本的敘述容易被讀成「中文版揭露較多、英文版隱瞞」。
實際情形是——**兩份文件各自省略了對該語言受眾而言「陌生」的第三方**：

- 中文受眾看得到百度與騰訊，看不到 Google
- 英文受眾看得到 Google，看不到百度與騰訊

→ **兩份都不是完整的揭露，而是各自針對受眾預期所做的取捨。**
   這個框架比「單向隱瞞」更貼近證據，也更難被反駁。

> **檢索有效性**：同一批檢索對 `Bugly`、`BaiduLBS` 皆有命中，
> 故零命中反映文本內容而非檢索失效。
> 另注意 `百度`、`Tencent` 皆為 0 次——廠商使用 SDK 名而非公司中文名，
> 這是 F01 曾誤判過的陷阱，檢索時必須同時涵蓋兩種寫法。

### 仍然是雙向缺口的部分

**阿里雲 ARMS（F14）與 GameSir（F09），在任何語言、任何版本中皆為 0 次。**
這兩者不屬於「對稱取捨」，而是**單純的未揭露**。

## 追加：繁中資源是簡中的機械轉換，在地化程度接近零（2026-08-25）

先前僅由 App 截圖觀察到「繁體字配中國用語」。
檢視反編譯後的資源檔，可將該觀察升級為**可重現的量化證據**。

### App 確實有繁體中文資源

```
static/1.6.8.0/resources/res/values-zh-rCN/strings.xml
static/1.6.8.0/resources/res/values-zh-rHK/strings.xml
static/1.6.8.0/resources/res/values-zh-rTW/strings.xml   ← 316 條字串
```

**所以不是「沒有繁中版」——繁中資源存在，只是內容是簡中的字元轉換。**

逐字比對可見：

```
zh-rCN:  账号密码将在重启后生效。假如1分钟内无法自动连接上飞行器，请手动连接WI-FI
zh-rTW:  賬號密碼將在重啟後生效。假如1分鐘內無法自動連接上飛行器，請手動連接WI-FI
```

**用詞完全相同，僅字元不同。**

### 量化：`values-zh-rTW` 中的用語分布

| 中國用語 | 次數 | 台灣用語 | 次數 |
|---|---|---|---|
| 設置 | 19 | 設定 | 1 |
| 屏幕 | 9 | 螢幕 | **0** |
| 點擊 | 9 | 點選 | **0** |
| 當前 | 6 | 目前 | **0** |
| 視頻 | 5 | 影片 | **0** |
| 網絡 | 4 | 網路 | **0** |
| 用戶 | 1 | 使用者 | **0** |
| 賬號 | 1 | 帳號 | **0** |
| 默認 | 1 | 預設 | **0** |
| 鏈接 | 1 | 連結 | **0** |
| 局域網 | 1 | 區域網路 | **0** |

```
中國用語合計 57 次    台灣用語合計 4 次
→ 中國用語佔 93.4%
```

**12 組對照中有 9 組完全只出現中國用語。**

### 判讀

`values-zh-rTW` 是自 `values-zh-rCN` 做**簡繁字元轉換**產生的，
**未進行任何用語在地化**。

這與本findings其他層級的觀察一致，並補上了**靜態、可重現**的一環：

| 層級 | 觀察 | 證據型態 |
|---|---|---|
| 官網 | 台灣區標「繁體中文」，供應簡體內文 | 動態 |
| App 介面 | 繁體字、中國用語 | 截圖 |
| 網路協定 | 送出 `language: zh_cn` | pcap |
| App 內部狀態 | `AreaCodeTello = TW` | shared_prefs |
| **App 資源檔** | **繁中資源 93.4% 為中國用語** | **靜態，可重現** |

### 觀測邊界

- 用語對照表為本研究自行選定的 12 組，**非窮舉**。
  不同的選詞會得出不同百分比，該數字應理解為**傾向指標**而非精確比例。
- 未比對 `values-zh-rHK`。

  （Android 依系統 locale 選擇，`zh-Hant-TW` 應命中 `values-zh-rTW`，但未實測驗證）。
