# F18 — 教學用的 API 就是攻擊用的 API：Tello SDK 規格中沒有任何認證

| 欄位 | 內容 |
|---|---|
| 編號 | F18 |
| 層級 | L1 近場 Wi-Fi / 教育場景 |
| 分類 | 設計缺陷 / 威脅模型 |
| 嚴重度 | **High**（承接 F16 的 Critical，本findings說明其適用場景） |
| 受影響版本 | 韌體層級，與 App 版本無關 |
| 狀態 | **T0 一手官方文件 + T2 實測交叉印證** |
| 對應計畫 | `docs/05-overnight-plan.md` P4 |

## 核心命題

**F16 所利用的協定，就是 Tello 官方提供給學生的教學 API。**

不是「類似」，是同一套：同樣的 UDP 埠、同樣的純文字指令、同樣的零認證。

## 一、官方 SDK 文件的一手證據

來源：`Tello SDK 2.0 User Guide`（Ryze 官方 CDN，8 頁）

### 連線方式與本研究實測完全一致

```
Tello IP: 192.168.10.1   UDP PORT: 8889     ← 指令（F16 送 command 的埠）
Tello IP: 192.168.10.1   UDP PORT: 8890     ← 狀態（F16 收到遙測廣播的埠）
Tello IP: 192.168.10.1   UDP PORT: 11111    ← 影像
```

> 「Before sending any other commands, send `command` to the Tello via UDP PORT 8889」

**這正是 F16 的攻擊步驟第一步**，逐字相同。

### 文件中的關鍵指令

| 指令 | 官方說明原文 |
|---|---|
| `command` | 進入 SDK 模式 |
| **`emergency`** | **"Stop motors immediately."** |
| **`rc a b c d`** | 直接搖桿控制（四軸） |
| **`wifi ssid pass`** | 設定飛機的 Wi-Fi 名稱與密碼 |
| `takeoff` / `land` | 起飛 / 降落 |
| `streamon` | 開啟影像串流 |
| `wifi?` | 查詢 Wi-Fi 訊號雜訊比 |

### 全文檢索：`auth` 出現 **0 次**

整份 8 頁的官方協定規格中，
**沒有任何關於認證、授權、配對或存取控制的敘述**。

`password` 一詞的 6 次出現，全部屬於 `wifi ssid pass` 這個「設定」指令的說明，
**而非用於保護協定本身**。

→ **零認證不是實作疏漏，是規格如此。**

## 二、與本研究實測的對照

| 官方文件 | 本研究實測 | 一致性 |
|---|---|---|
| `command` 進入 SDK 模式 | F16：18 ms 回 `ok`，未經任何認證 | ✅ |
| 狀態廣播至 8890 | F16：431 個明文遙測封包 | ✅ |
| `rc a b c d` 為有效指令 | TC-L1-12：對照組確認被識別 | ✅ |
| `wifi?` 查詢 SNR | TC-L1-11：回 `90` | ✅ |
| `emergency` 立即停止馬達 | **未實測**（見觀測邊界） | — |

**本研究的實測結果與官方規格逐項吻合。**

## 三、教學工具用的是同一套協定

### Python：`djitellopy`

主流的 Tello Python 函式庫，官方說明為
「using the official Tello SDK and Tello EDU SDK」。

其運作方式為：對 `192.168.10.1:8889` 送出 `command` 進入 SDK 模式，
自 8890 讀取狀態，以 `streamon` 開啟影像。

→ **學生課堂上寫的第一行 `tello.connect()`，
   送出的就是 F16 用來切斷擁有者影像的那 7 個位元組。**

### Scratch：`Tello.js` + `Tello.s2e`

官方提供的 Scratch 2.0 擴充採 Node.js HTTP 橋接：
自 Ryze 官網下載 `Tello.js` 與 `Tello.s2e`，
以 `node Tello.js` 執行後於 Scratch 匯入實驗性 HTTP 擴充。

該橋接層最終仍是對 UDP 8889 送出同一組文字指令。

## 四、教室場景的威脅模型

### Tello EDU 的多機編隊是官方主打功能

官方與經銷商的產品說明皆強調「可控制多台 Tello EDU 編隊飛行」。
典型的 STEM 課堂即為**一間教室內多台無人機同時運作**。

而依 **F12** 實測，Tello 的 Wi-Fi 預設為 **`open`（無密碼）**，
且該預設由廠商自己的字串確認（見 F16）：

> 「飛行器**默認無密碼**」

### 由此推得的教室情境

| 條件 | 依據 |
|---|---|
| 一間教室內數台至數十台無人機 | 官方多機編隊功能 |
| 每台皆為開放 Wi-Fi | F12 實測 + 廠商字串 |
| 協定零認證 | 官方 SDK 規格（本findings） |
| 學生已具備完整的操作 API 與工具 | 課程本身即在教授 |

→ **任一學生都能連上其他同學的無人機並送出指令，
   而所需的全部知識，正是課程正在教的內容。**

依 F16 已實測的效果，至少可造成：
**切斷他人的影像連線，且該連線只能以關閉飛機電源恢復**。

## ⚠️ 觀測邊界

- **未在真實教室環境測試**，亦**未取得第二台 Tello**。
  上述教室情境為「官方文件 + 本研究單機實測」推得，
  **非實地驗證**。多機同時運作時 SSID 是否可區分、
  學生裝置是否可能誤連，皆未測。
- **未測試 `emergency`、`takeoff`、`land`、`rc` 對飛行中機體的實際效果。**
  官方文件記載 `emergency` 為「立即停止馬達」，
  但**本研究從未送出該指令**。
  「可使飛機墜落」仍屬**依官方文件的推論**，非實測。
- **未測試 `wifi ssid pass`**。若該指令同樣無需認證，
  攻擊者可改掉飛機的 Wi-Fi 憑證，
  使擁有者須長按電源鍵 5 秒原廠重置才能恢復。**此為推論。**
- 教學資源的檢索**非窮舉**。本次查閱的中文教學資源中未見
  「設定 Wi-Fi 密碼」的指引，但**不能據此斷言所有教材皆未提及**。
- `djitellopy` 與 `Tello.js` 的實作**未逐行審閱原始碼**，
  其協定用法係依官方說明與文件推得。
