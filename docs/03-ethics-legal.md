# 倫理與法規邊界

> 報告中應獨立成章。寫得好是加分項，不是形式。

## 硬性紅線（不得跨越）

1. **只測自有設備與自有帳號。** 不對他人持有的無人機或帳號做任何測試。
2. **不對他人裝置發動 de-auth。** 去認證攻擊會影響同頻段的其他使用者。
   複現時必須：自有無人機、自有測試手機、遮蔽或人煙稀少環境、確認附近無其他 Tello。
3. **不對 Ryze/DJI 生產後端做主動測試。** 不掃描、不 fuzz、不試帳號、不壓測。
   本專案對後端**只做被動流量觀察**（自己的 App、自己的帳號、自己的流量）。
4. **不散布** 破解後的 APK、韌體、或可直接武器化的完整攻擊工具。
   PoC 以「足以證明問題存在」為限，不提供 turnkey 攻擊程式。
5. **去識別化**：報告與 pcap 附件中，自己的帳號、email、裝置識別碼、GPS 座標一律遮蔽。

## 台灣法規對照

| 行為 | 可能涉及 |
|---|---|
| 未經授權存取他人無人機／帳號 | 刑法第 358 條 無故入侵電腦罪 |
| 干擾他人設備運作（de-auth、指令注入） | 刑法第 360 條 干擾電腦系統罪 |
| 取得他人資料 | 刑法第 359 條 無故取得刪除變更電磁紀錄罪 |
| 無線電干擾 | 電信管理法相關規定 |
| 處理含個資的流量／截圖 | 個人資料保護法 |
| 實際飛行 | 民航法「遙控無人機管理規則」——場域、高度、禁航區、日夜間限制 |

> 逆向工程本身在台灣為研究目的通常可主張合理使用，但**散布破解成果**是另一回事。
> 若有疑慮，向指導老師或學校法務確認。

## 飛行安全（Phase 3）

- 室內或空曠處，低空
- 電池充足，備妥手動斷電方式
- 測試「控制權接管」時，無人機應在**可徒手接住的高度**（< 1.5 m）
- 全程錄影（也是 PoC 素材）
- 現場至少兩人：一人操作、一人負責物理攔截

## 責任揭露流程

若發現**新的、可歸責的**漏洞（非前人已公開者）：

1. 撰寫技術細節，含重現步驟與影響評估
2. 聯繫 Ryze / DJI 安全窗口（DJI 有 Bug Bounty 計畫，需先確認目前是否仍受理 Tello 產品線）
3. 給予 **90 天**修補期（產品已停售，廠商可能不回應——這個結果本身應如實記錄）
4. 同步知會 TWCERT/CC
5. 期限屆滿或廠商確認修補後再公開

> **重要**：Tello 已停產停售。廠商可能完全不回應。
> 這時的正確做法是：**公開時淡化可直接複製的攻擊細節**，強調防護建議與棄養裝置的政策意涵，
> 而不是因為「反正沒人維護」就完整公開武器化細節。
