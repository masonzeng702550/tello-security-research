# TC-L1-03 現場測試程序：控制指令注入

> **目的**：把 F12 的「依協定屬性推論可注入」轉為**直接證據**。
> **本文件為現場操作用**，每一步都要能在戶外照著做。

## 為什麼需要這場測試

F12 已確立三項事實：Wi-Fi 為 `open`、控制封包明文、搖桿指令序號恆為 0。
由此**推論**任意來源可注入飛行指令。

但推論不等於證據。F06 的 TC-L1-06 只驗證了 SDK 文字協定的重放，
**App 私有協定的偽造封包從未實際送出過**。

本測試補上這一步。

## 工具狀態：已就緒且已驗證

| 項目 | 狀態 |
|---|---|
| CRC8 參數 | `poly=0x8c init=0x77 reflect` — 暴力搜尋求得，16,849 封包全數吻合 |
| CRC16 參數 | `poly=0x8408 init=0x3692 reflect` — 16,849 封包全數吻合 |
| 封包編碼器 | `tools/tello_inject.py` — **11,693 個搖桿封包往返後位元組完全相同** |
| 安全機制 | 預設 dry-run；偏移需 `--arm`；偏移量上限 200；時長上限 3 秒 |

> 往返驗證是本工具正確性的**決定性依據**：
> 解碼實測封包後重新編碼，若能還原出完全相同的位元組，
> 即證明編碼邏輯正確——與欄位語意的命名是否精確無關。

## 前置條件（缺一不可）

- [ ] **戶外空曠場地**，半徑 10 公尺內無人、無車、無玻璃帷幕
- [ ] 風速小，非雨天
- [ ] 飛機電量 > 50%
- [ ] **飛機已完成六面 IMU 校準**，`ERROR CODE 29` 已排除
      —— 帶著飛控告警做注入測試，結果無法歸因
- [ ] 電腦已連上 `TELLO-xxxxxx` Wi-Fi
- [ ] 另備一支手機開著 Tello App（作為正常控制端與緊急降落手段）
- [ ] 已閱讀 `docs/03-ethics-legal.md`

## 階段一：飛機在地面，不轉槳（零風險）

**目的**：確認飛機是否接受本工具構造的封包，全程不涉及飛行面。

```bash
# 1. 確認可達
ping 192.168.10.1

# 2. 背景擷取（記錄飛機是否有回應）
tcpdump -i <介面> -w TC-L1-03-ground.pcap host 192.168.10.1

# 3. 先 dry-run，確認封包內容合理
python tools/tello_inject.py --neutral

# 4. 實際送出中位搖桿封包（所有軸皆為 1024，理論上不產生任何動作）
python tools/tello_inject.py --neutral --send --seconds 1
```

**觀察重點**：飛機是否在 `8889 → <我方埠>` 方向回覆任何封包。

- **有回覆** → 飛機接受了未經認證的來源，**注入前提成立**
- **無回覆** → 可能存在連線層綁定，記錄後進入階段二判斷

> 此階段即使飛機接受封包也**不會起飛**——中位搖桿等同「不操作」，
> 且飛機未解鎖時搖桿指令不會驅動馬達。

## 階段二：飛機懸停中，單軸微幅偏移

**僅在階段一有回覆時才進行。**

```bash
# 由正常手機起飛並懸停穩定後執行
python tools/tello_inject.py --axis 2 --offset 80 --arm --send --seconds 0.5
```

`offset=80` 相對於滿舵 660 約為 **12%**，屬微幅。

**觀察重點**：飛機是否產生對應該軸的可見位移。

- **有位移** → **注入成功，F12 的推論成為實測證據**
- **無位移** → 記錄，並嘗試提高送出頻率（見階段三）

## 階段三：競爭條件（僅在階段二無效時）

手機以 50 Hz 持續送指令。若我方封包被「最後到達者勝」規則覆蓋，
提高頻率應能取得優勢。

```bash
# 將間隔由 20ms 縮短（需修改 send() 的 delay 參數）
```

> **本階段風險較高**，兩個控制源競爭可能導致飛機抖動。
> 執行前務必確認場地淨空，且手指放在正常手機的降落鍵上。

## 中止條件（任一發生即立刻停止）

1. 飛機出現非預期的劇烈動作
2. 飛機朝人或障礙物移動
3. 電量低於 30%
4. 任何一次注入產生超出預期幅度的反應

**中止方式**：正常手機按降落；若失控，直接**關閉飛機電源**（機身側鍵長按）。

## 記錄要求

每個階段都必須留下：

- `tcpdump` 完整 pcap
- 送出的封包 hex（工具會印出）
- 飛機行為的影片或文字描述
- 時間戳，供與 pcap 對照

依 `README.md`：**沒記錄的實驗等於沒做過。**

## 結果如何寫回 findings

| 結果 | 對 F12 的影響 |
|---|---|
| 階段一有回覆、階段二有位移 | 狀態由 T2 升為**直接實測**，移除「注入未實測」的觀測邊界 |
| 階段一有回覆、階段二無位移 | 記錄為「接受封包但存在其他約束」，F12 嚴重度維持但需補述 |
| 階段一無回覆 | **F12 的推論被削弱**，須誠實記載並重新評估嚴重度 |

> 第三種結果同樣有價值。若飛機拒絕陌生來源，那是本研究**否證自己推論**的紀錄，
> 必須照實寫。
